# Starter validation

The kit is a local Git repository and an npm-compatible package. Nothing has been published or deployed.

The bundled snapshot was validated on 2026-10-01 with vinext 1.0.0 and TanStack Start 1.168.59. Both frameworks, with and without sample navigation, passed TypeScript, Oxlint, Oxfmt, Knip, production builds, deployment dry-runs, and React Doctor at 100/100. A real npm installation and Bun installation were exercised. The npm tarball was also executed through npm exec and bunx from outside the checkout.

The latest-release checks also passed with vinext 1.0.1 and TanStack Start 1.168.60 (Router 1.170.41), through both Bun and npm.

The production browser suite verifies desktop/mobile navigation, matching background colors, theme persistence, back navigation, reduced motion, native modified clicks, PWA manifest and offline fallback, and byte-identical screenshots across frameworks at both viewport sizes in both themes.

[Lighthouse measurements](lighthouse-compressed.json) retain three cold browser runs for each framework and each standard mobile/desktop preset. Lighthouse 13.5.0 reported 100 in Performance, Accessibility, Best Practices, and SEO in all twelve runs. The target was a built local Workers preview behind an explicitly labeled gzip transport simulation. It compressed responses without changing app content, caching pages, changing presets, or disabling audits. The score summaries are retained here. Temporary smoke builds and browser profiles were removed after verification at the user’s request.

These are local measurements, not deployed Cloudflare scores. Cloudflare's edge normally compresses responses; workerd's local preview does not. Raw local previews also produced 100 scores after the CSS fix, but repeated raw runs varied below 100, including when other builds consumed CPU. The budget script correctly failed those runs. The recorded compression results do not guarantee 100 on every device, shared runner, or future app; rerun the included three-run budget against an authorized deployed preview before release.

PWA installability and offline behavior were tested separately from Lighthouse's four stable categories. Chrome DevTools MCP configuration is included for future trusted agent sessions; this running session used the Lighthouse CLI and Playwright rather than claiming a newly connected MCP server.

The page-transition fix was validated on 2026-10-01 with the bundled dependency snapshot. All four framework/navigation smoke fixtures passed through Bun and npm. The final production navigation suite passed all 11 tests, including frame-by-frame checks that cached routes keep the outgoing content through exit and start the destination near zero opacity. Browser Back cancels an interrupted transition. Additional production checks covered the bare fixtures in both themes and viewport sizes; their generated app names were normalized only for screenshot comparisons.

[Page-transition Lighthouse measurements](lighthouse-page-transitions.json) retain twelve serial cold runs against the corrected, uncompressed local production previews using standard mobile and desktop presets. Vinext mobile and TanStack desktop scored 100 in all four categories. Vinext desktop scored 99 Performance in all three runs; TanStack mobile scored 88, 87, and 88 Performance. Accessibility, Best Practices, and SEO scored 100 throughout. The strict budget correctly failed the two affected presets. These are raw preview measurements, not compression simulations or deployed results; reports identified document compression and framework JavaScript costs. Full JSON/HTML reports remain with the temporary fixtures at /tmp/starter-smoke-ZRji1A.

The follow-up performance fix splits TanStack's initial entry into a 2.45 KB bootstrap that immediately loads React, React DOM, and StartClient in parallel, then hydrates the server-rendered document. It follows TanStack's [custom client entry point](https://tanstack.com/start/latest/docs/framework/react/guide/client-entry-point) API. The full framework runtime still loads; its bulk is removed from the parser-discovered initial module graph. Tailwind source detection now targets application source, keeping tooling and documentation examples out of generated utilities.

A matched-version raw mobile experiment with TanStack Start 1.168.59 reduced simulated first paint from about 3.0 s to 0.79 s and LCP from about 3.2 s to 1.09 s, scoring 100 in all four categories with zero blocking time and layout shift. Fresh follow-up fixtures used the latest frameworks, vinext 1.0.1 and TanStack Start 1.168.60 (Router 1.170.41), while retaining the three-day tooling policy. All four framework/navigation smoke combinations passed through Bun and npm, including production builds and deployment dry-runs. All 13 production navigation tests passed, including visible content and working native navigation with JavaScript disabled. Additional browser checks verified both bare fixtures and screenshot parity across themes and viewport sizes, normalizing only the generated bare-app names.

[Bootstrap Lighthouse measurements](lighthouse-bootstrap.json) record 24 serial cold audits using Lighthouse 13.5.0, standard mobile/desktop presets, and all four stable categories. Twelve runs measured raw local production previews and twelve measured the explicitly labeled local gzip simulation. TanStack scored 100 in all four categories in every run. Vinext raw Performance was 100/100/99 on mobile and 100/99/99 on desktop. Its gzip simulation scored 100/99/100 Performance on mobile and 100/100/100 on desktop. All Accessibility, Best Practices, and SEO scores were 100. The strict budget correctly failed the three Vinext presets containing 99; no audits or presets were changed to pass. These local measurements do not prove deployed scores. Full reports are retained under /tmp/starter-smoke-Fq51VA/audit-results/.
